# Сценарий показа (15 минут)

Показ идёт на живой платформе с учебной группой, которой ещё нет, поэтому за день до него делают
демонстрационный класс, а сразу после показа его убирают. Всё ниже проверено на локальной копии.

## За день до показа

На сервере (в таком порядке; подробности в `PILOT.md`):

```bash
python manage.py migrate
python manage.py seed_course
python manage.py set_course_owner python-intro <логин_преподавателя>
python manage.py set_course_owner python-continued <логин_преподавателя>
python manage.py sync_course_protection            # варианты заданий, «ещё не проходили», вопросы «объясни»
python manage.py seed_demo_cohort --teacher <логин_преподавателя>   # 24 демо-ученика (demo_01 ... demo_24)
python manage.py pilot_check                        # предупреждения про демо-учеников и ключи ожидаемы
```

Проверьте руками:

- `python manage.py check_runner` на сервере проходит: на Railway код уходит в публичный Judge0 (Docker не нужен),
  а он бывает занят. Раннер сам повторяет запрос и ставит запуски в очередь; если проверка упала, ученик увидит
  «Проверяющая служба сейчас занята», а попытка не засчитается. Для показа надёжнее свой Judge0 (`RUNNER_JUDGE0_URL`).
- Для Мудреца задан `GEMINI_API_KEY`; без него кнопка честно отвечает «Мудрец сейчас недоступен».
- Ученикам скажите регистрироваться под прозвищем: имя видно всем в таблице лидеров (под полем есть подсказка).
- Заведён свой тестовый ученик: регистрация без почты активирует аккаунт сразу.
- В кабинете преподавателя виден класс (если пусто, курсы не закреплены за преподавателем).

## Показ

**Ученик (6 минут).**

1. Регистрация без почты: вход происходит сам, открывается карта миров. Сверху строка «Продолжить».
2. Миссия II, кодовый шаг «Испытание Оракула»: у каждого ученика свои числа в условии, поэтому чужой
   готовый ответ не подойдёт.
3. Три неудачных запуска: появляется баннер помощи с кнопками. Зелье Ясности даёт подсказки по одной,
   Свиток Архитектора каркас, Мудрец отвечает на вопросы и не пишет решение.
4. Шаг решён: +XP виден сразу, за ним вопрос «Объясни своё решение» про собственную программу.
5. Миссия завершена: окно со звёздами, затем «Мой путь» (что получилось, где было трудно, что дальше) и
   таблица лидеров (общий зачёт и зачёт курса, своя строка отмечена).

**Преподаватель (8 минут).**

1. Кабинет: сводка, список «Кому нужна помощь сейчас» с причинами (шаг и число неудач подряд, долгое молчание).
2. Блок «С кого начать разговор о решениях», затем страница такого ученика.
3. На странице ученика блок «Самостоятельность решений»: сам, с подсказкой, со скелетом, с Мудрецом; признаки
   (вставленный код без правок, непройденные конструкции, такая же структура у другого ученика, неверные
   ответы на «объясни»). Показать оговорку: признаки только подсказка для разговора.
4. Аналитика: завершение миссий, попытки до успеха, отсев по шагам, воронка «история → квиз → код →
   объяснение», кривая неудач подряд с порогом, эффект подсказок и Мудреца.
5. Студия: у кодового шага поля «Персональные варианты» и «Ещё не проходили».

## Что сказать о границах

- Внешний ИИ платформа не блокирует и не может заблокировать. Она честно размечает помощь, которую дала сама,
  замечает признаки внешней помощи и делает готовый ответ бесполезным. Навык надёжно подтверждают
  контрольная точка на занятии и разговор о решении.
- Признаки приходят из браузера ученика и могут быть неполными; по ним не ставят оценку.
- Обученной модели риска пока нет: конвейер обучения готов и проверен на выдуманной таблице, но OULAD не скачан
  (официальная ссылка не открывается), а данных пилота ещё нет. Поэтому список преподавателя сейчас работает
  по правилам (неудачи подряд, молчание), а причина «модель» появится после обучения на данных пилота.
- Демо-класс выдуманный. Метрики на нём показывают, как выглядит кабинет, а не результат исследования.

## После показа

```bash
python manage.py seed_demo_cohort --remove          # убрать демо-учеников
python manage.py pilot_check                        # без предупреждений про демо-учеников
```
