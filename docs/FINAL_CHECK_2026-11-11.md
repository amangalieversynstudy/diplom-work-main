### Название против содержания
- «Анализ поведенческих паттернов» — покрыто слабо. Определены четыре профиля (самостоятельный, с опорой на помощь, проб и ошибок, прерывистый) каскадом экспертных правил с порогами 0,40 / 2 / 2,5 / 2,0 / 3,0 (backend/game/patterns.py:31-66, docs/METRICS.md:59-63). Метод прозрачный, но это классификация по заранее придуманным порогам, а не анализ: пороги не выведены из данных, нет кластеризации, анализа последовательностей, проверки устойчивости. Сверка с кластерным анализом (ARI) обещана только в учебном задании вне git; кода для неё нет. Результатов нет ни на каких данных. Уверенность высокая.
- «Паттерны» — три дефекта определения, которые комиссия найдёт сама: профиль ставится после одного шага (patterns.py:31); правила накопительные (одна вставка после ухода со вкладки за шесть недель или два обращения за помощью), поэтому профиль зависит от объёма активности; профиль считается за весь период, а не на раннюю дату, то есть связь с итоговым баллом будет одновременной, а не прогностической.
- «Прогнозирование учебной результативности» — покрыто частично. Целевая переменная на платформе задана: балл 0–100 = 50% доля решённых шагов + 30% доля звёзд + 20% доля верных «объясни решение»; в коде (backend/game/metrics.py:59-62) и в документе (docs/METRICS.md:55-57) одинаково, зафиксирована 2026-10-28 (коммит fd8bfbc), до сбора данных. В docs/PILOT.md формула упомянута одной фразой (строка 3), полной записи с порогами уровней там нет.
- «Прогнозирование» — фактически сделано другое: классификация «неуспешный исход курса» на OULAD и «уход на 14 дней» на платформе. Прогноза самого балла нет ни на одних данных (в ml/data/out_oulad/report.json нет performance_regression). Модели: логистическая регрессия, градиентный бустинг, Ridge. Проверка грамотная: тест на более позднем наборе 2014J, порог заморожен на валидации, парный бутстреп по студентам, эталон из одного признака (ml/risk/train.py, ml/data/OULAD_RESULTS.md:3).
- Результат на OULAD подан честно: ROC AUC 0,65–0,67, модель хуже счётчика активных дней на 0,014 [−0,019; −0,008], precision почти на уровне случайной раздачи (ml/data/OULAD_RESULTS.md:14,33-36). Для диссертации это означает: тезис «модель прогнозирует» защищать нельзя; защищаемый тезис — «проверено с интервалами, что усложнение не даёт выигрыша над простым индикатором активности; для ранней диагностики достаточно объяснимых правил». Отрицательный результат допустим, но его надо сделать положением на защиту, а не сноской.
- Утечка «часть–целое» в прогнозе балла: шаги первого окна входят в итоговый балл, а звёзды вычисляются из числа лишних попыток (backend/game/services.py:175-183), которое является признаком модели. Высокий R² будет частично арифметикой. В учебном задании это признано для профилей, для регрессии балла — нет.
- «В интерактивной геймифицированной веб-платформе» — только обстановка. Игровые механики не являются ни фактором, ни признаком: события магазина, таблицы лидеров, серий, Таверны в след не пишутся (backend/game/models.py:627-651), контрольного условия без геймификации нет, docs/PASSPORT.md:17 прямо называет механики «источником данных и средой вмешательства». Вопрос «что в ваших выводах специфично для геймификации?» останется без ответа.
- Гипотезы H1–H4 унаследованы от прежней темы (раннее предупреждение отсева, BI-дашборд): ни одна не про паттерны и не про прогноз результативности. Соответствующие названию H5 и H6 есть только в документе вне репозитория и в протокол не внесены.

- [высокий] Карта: доступная миссия помечена красным значком, похожим на крестик; подписи узлов только по наведению; легенды нет (`frontend/pages/worlds/index.js`).

- [высокий] Меню «Класс» (класс героя) рядом с «У меня есть код класса» (группа преподавателя).
- [средний] Кнопки «Принять вызов», «Произнести ответ» вместо «Далее», «Ответить»; «Лучшая попытка: 0», «В пути: 5 мин», «Результативность 4.3» без пояснений.
