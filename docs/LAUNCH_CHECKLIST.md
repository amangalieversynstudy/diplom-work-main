# Запуск пилота: что делать владельцу, по шагам

Даты в примерах: репетиция 10–15 ноября, пилот с понедельника **16 ноября** по **28 декабря 2026** (6 недель,
как в `PILOT.md`). Если даты другие — замените их везде одинаково. Подробности находок — в
`FINAL_AUDIT_2026-11-10.md`.

Адреса: сайт `https://diplom-work-main-frontend.vercel.app`, сервер
`https://diplom-work-main-production.up.railway.app`.

Названия кнопок в панелях Vercel и Railway даны по их документации; если кнопка называется чуть иначе, ищите по
смыслу.

### 1.1. Railway: переменные сервера

Railway → проект → сервис бэкенда → вкладка **Variables** → **New Variable** (или **Raw Editor**, чтобы вставить
всё разом). Каждая строка — одна переменная:

```
PILOT_STARTED_AT=2026-11-16T00:00:00+05:00
PILOT_ENDED_AT=2026-12-28T00:00:00+05:00
HELP_OFFER_SHARE=50
SOCIAL_ENABLED=0
ANALYTICS_EXPORT_SALT=<случайная строка, см. ниже>
TEACHER_INVITE_CODE=<свой код, см. ниже>
FRONTEND_URL=https://diplom-work-main-frontend.vercel.app
```

| Переменная | Что делает |
|---|---|
| `PILOT_STARTED_AT` | начало пилота. В исследование попадают только те, кто зарегистрировался с этого момента: аккаунты репетиции отпадут сами. Обязательно со временем и `+05:00`; просто дата не работает |
| `PILOT_ENDED_AT` | конец активного периода: после него ночные снимки не пишутся |
| `HELP_OFFER_SHARE` | `50` — половине учеников показывается баннер помощи после трёх неудач (гипотеза H2). Без этой строки контрольной группы нет |
| `SOCIAL_ENABLED` | `0` выключает Таверну на время пилота: обмен подсказками искажает H2. Решение записать в `PILOT.md` |
| `ANALYTICS_EXPORT_SALT` | из неё строятся псевдонимы учеников в выгрузке. **Задать один раз и не менять до конца**, сохранить у себя: она понадобится при выгрузке |
| `TEACHER_INVITE_CODE` | код, по которому регистрируется преподаватель. Публичный `PILOT-2026` на сервере не принимается |
| `FRONTEND_URL` | адрес сайта: для ссылок в письмах и для разрешения запросов с сайта |

**Как получить случайную строку.** В PowerShell в папке проекта:

```
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

Скопируйте результат в `ANALYTICS_EXPORT_SALT`. Запустите ещё раз с числом `12` вместо `48` — это будет
`TEACHER_INVITE_CODE`. Оба значения сохраните в менеджере паролей, в чат и в git не кладите.

**Проверьте, что уже стоит** (сервер работает, значит, скорее всего, заданы): `DJANGO_SECRET_KEY`,
`DATABASE_URL`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`, `DJANGO_SUPERUSER_PASSWORD`.

**Чего быть не должно** (если есть — удалить): `RUNNER_ALLOW_UNSAFE_FALLBACK`, `ALLOW_DEMO_SEED`,
`RISK_MODEL_PATH`, `ENABLE_STREAK_SCHEDULER`.

**По желанию:**

- `RESEND_API_KEY` — на пилот лучше не включать, пока не проверена доставка: с включённой почтой ученик,
  указавший e-mail, не войдёт, пока не откроет письмо.
- `RUNNER_JUDGE0_URL`, `RUNNER_JUDGE0_KEY`, `RUNNER_JUDGE0_CONCURRENCY=8` — если купили ключ Judge0 на RapidAPI.
  Без них код проверяет бесплатный общий сервер: при 30 учениках запуск ждёт 5–15 секунд.
- `GEMINI_API_KEY` — включает Мудреца. Без ключа ученик видит «Мудрец сейчас недоступен»; с ключом вопрос и код
  уходят в Google, это надо написать в информационном листе.

После сохранения переменных Railway сам перезапустит сервер (1–3 минуты). Поэтому менять переменные во время
занятия нельзя.

### 1.2. Vercel: чтобы сайт обновился

1. Vercel → проект фронтенда → **Settings** → **Environments** → **Production** → **Branch Tracking** →
   выбрать `feature/final-polish` → **Save**. (В старом интерфейсе: Settings → Git → Production Branch.)
2. Вкладка **Deployments** → верхняя строка с веткой `feature/final-polish` → меню **⋯** → **Redeploy** (или
   **Promote to Production**).
3. Дождаться статуса **Ready** (2–4 минуты). Если **Error** — открыть лог; строка `Module not found …
   studioSteps` значит, что шаг 1.0 не сделан.

**Как убедиться, что обновилось:**

- в Deployments у верхней строки метка **Production** (**Current**) и ветка `feature/final-polish`;
- на сайте нажать Ctrl+U, затем Ctrl+F, найти `buildId`: значение **не** `Fbi8zizqFtfvEyO5mQEXs`;
- войти учеником, выбрать класс героя и открыть карту: у класса свой мир («Змеиные руины» и т. п.);
- пункта «Таверна» в меню нет (если задан `SOCIAL_ENABLED=0`).

### 1.3. Railway: два Cron-задания

Для каждого: проект → **+ New** → **GitHub Repo** → тот же репозиторий, ветка `feature/final-polish`. В
**Settings** нового сервиса: Dockerfile Path = `Dockerfile.backend`, затем **Custom Start Command** и
**Cron Schedule** из таблицы. Публичный домен сервису не нужен.

| Сервис | Custom Start Command | Cron Schedule | Зачем |
|---|---|---|---|
| snapshot | `python manage.py snapshot_early_warning` | `0 19 * * *` | каждую ночь (19:00 UTC = полночь по +05:00) записывает список «срочно / внимание / норма». Пропущенный день для H3 потерян навсегда |
| prune | `python manage.py prune_learning_data` | `0 3 * * *` | удаляет журнал старше срока хранения (730 дней) |

**Переменные обоих Cron-сервисов должны совпадать с сервером.** Проще всего: в сервисе бэкенда вынести
переменные в **Shared Variables** проекта и подключить их к обоим Cron. Минимум: `DATABASE_URL`,
`DJANGO_SECRET_KEY`, `ALLOWED_HOSTS`, `PILOT_STARTED_AT`, `PILOT_ENDED_AT`.

Проверка: на следующий день в **Logs** сервиса snapshot строка `snapshot 2026-11-11: N learner(s)` или
`nothing to do` (пока согласившихся нет, это нормально).

### 1.4. Преподаватель пилота

1. Преподаватель регистрируется на сайте: «Я преподаватель», код из `TEACHER_INVITE_CODE`.
2. Вы открываете `https://diplom-work-main-production.up.railway.app/admin/`, входите суперпользователем →
   **Пользователи** → этот преподаватель → включить **Статус персонала**, снять флаг **преподаватель** →
   Сохранить. Без этого он не увидит учеников основных курсов.
3. На сервере (как запускать команды — в шаге 1.5):

```
python manage.py set_course_owner python-intro <логин_преподавателя>
python manage.py set_course_owner python-continued <логин_преподавателя>
python manage.py seed_demo_cohort --remove
```

### 1.5. Проверка сервера одной командой

Один раз установить Railway CLI (`npm i -g @railway/cli`), затем в PowerShell в папке проекта:

```
railway login
railway link
railway ssh
python manage.py pilot_check
```

`railway link` спросит проект и сервис — выбрать бэкенд. Внутри `railway ssh` команды идут на самом сервере.
Результат: **ни одной строки `[FAIL]`**. Строки `[WARN]` прочитать; ожидаемые — про публичный Judge0, про
почту, про Мудреца. Выход из сервера: `exit`.

### 1.6. Остальное до старта

- Railway → Postgres → **Backups**: включить ежедневные копии и сделать одну вручную.
- Дописать информационный лист (`PILOT.md`, раздел 3): контакт; код запускается на стороннем сервере Judge0;
  Зал славы открыт без входа; код последней попытки хранится в записи о шаге. Получить согласование
  научного руководителя.
- GitHub → Settings → Code security: включить Secret scanning и Dependabot security updates.

## 2. Репетиция на 2–3 знакомых (до 15 ноября)

Каждый проходит это на своём устройстве, один — с телефона.

| № | Что нажать | Что должно получиться |
|---|---|---|
| 1 | Сайт → «Регистрация» → «Я ученик», логин-прозвище, пароль от 8 символов, **почту не указывать**, поставить галочку согласия → «Создать аккаунт» | сразу вход и карта миров, без письма. Слишком простой пароль (`12345678`, `qwerty123`) сервер не примет — это правильно |
| 2 | Выбрать класс героя | карта этого класса, первая миссия открыта |
| 3 | Открыть первую миссию, пройти шаги: текст, квиз, код → «Запуск» | код выполняется за несколько секунд, верное решение засчитывается, миссия завершается, начисляется опыт |
| 4 | В квизе ошибиться 3 раза подряд; в кодовом шаге — 3 раза подряд | примерно у половины появляется баннер помощи, у остальных нет — так и задумано |
| 5 | Использовать зелье ясности на открытом шаге | подсказка показана, предмет списан |
| 6 | Выйти и войти снова | прогресс на месте |
| 7 | Вы: войти преподавателем → `/teacher` | видны все репетиционные ученики, их шаги и ошибки; в списке предупреждений ошибавшиеся 3 раза — «внимание», 5 раз на одном шаге — «срочно» |
| 8 | Вы: на следующий день → Railway → Cron snapshot → Logs | строка `snapshot <дата>: N learner(s)`, где N — число репетиционных учеников с согласием. (Если `PILOT_STARTED_AT` уже задан датой 16 ноября, будет `nothing to do`: репетиция в исследование не входит. Тогда проверьте только, что задание запустилось без ошибки) |
| 9 | Вы: `/admin/` → Пользователи → один из учеников → смена пароля | ученик входит с новым паролем. Это ваш способ помочь забывшему пароль |
| 10 | Вы: `railway ssh` → `python manage.py pilot_check` | без `[FAIL]` |

Если что-то из 1–7 не получилось — старт переносится, сначала исправление.

## 3. В день занятия

**До занятия (за час):** открыть сайт и `/healthz` сервера (должно быть `{"status": "ok"}`); войти
преподавателем; ничего не менять в Railway и Vercel.

**Что сказать ученикам:**

1. «Регистрируйтесь как ученик. Логин — прозвище, не настоящее имя: его видно в Зале славы. Почту не
   указывайте. Логин и пароль запишите: без почты пароль восстановить можно только через меня».
2. «Галочка про исследование добровольная и на оценку не влияет. Если согласны — поставьте её сейчас: данные
   пойдут в исследование без имени. Отозвать можно в профиле». Раздать информационный лист.
3. «После регистрации выберите класс героя и начинайте с первой миссии. Класс меняет только вид карты, задания
   у всех одни».
4. «Если запуск кода думает 10–15 секунд — подождите, не нажимайте много раз».
5. «Некоторым платформа будет предлагать помощь после нескольких ошибок, некоторым нет. Подсказки и так доступны
   всем».

**Чего не делать:**

- не менять переменные, не нажимать Redeploy, не выкладывать код во время занятия и весь пилот (кроме
  исправления ошибок; каждое записать с датой);
- не включать Таверну, почту и модель риска посреди пилота;
- не регистрировать учеников самому и не входить под их аккаунтами;
- не помогать только тем, кого показал список «срочно», не записав контакт (см. раздел 4);
- не называть вслух, кто в какой группе эксперимента.

**Что смотреть в кабинете (`/teacher`):** живая панель — все ли появились и двигаются; кто застрял на одном
шаге; список предупреждений. В конце занятия: `railway ssh` → `python manage.py pilot_check` → строка
«Согласились на исследование: X из Y». Если меньше 80% — напомнить про галочку в профиле на следующем занятии.

## 4. Каждый день и раз в неделю

**Каждый день (2 минуты):**

1. Railway → Cron snapshot → Logs: есть строка `snapshot <вчерашняя дата>: N learner(s)`.
2. Открыть `/healthz`.
3. Если говорили с учеником из «срочно» или «внимание» — строка в свой файл `contacts.csv`:

```
username,date
nick_one,2026-11-18
```

**Раз в неделю (10 минут):**

1. `railway ssh`, затем `python manage.py pilot_report` — выделить весь вывод, скопировать в файл `week-N.md`
   на своём компьютере (в контейнере файлы пропадают).
2. В отчёте по порядку: сбои песочницы (больше 2% — чинить в первую очередь; больше 5% — стоп); сколько
   учеников без согласия и без следа; список «срочно».
3. Railway → Postgres → Backups: свежая копия есть.
4. В первую и в последнюю неделю: преподаватель заполняет анкету SUS внизу страницы `/teacher`.

## 5. Если что-то сломалось

| Что случилось | Что делать |
|---|---|
| **Песочница занята**, код не запускается или ждёт дольше 30 секунд | Попросить не нажимать «Запуск» повторно и запускать по рядам. Проверить `/healthz`. Если не проходит 10 минут — перейти к шагам без кода (текст, квизы) и записать дату и время. Надёжное решение — ключ Judge0 (шаг 1.1, «по желанию»), но ставить его после занятия |
| **Ученик не может войти** | Проверить логин (регистр не важен в почте, но важен в пароле). Забыл пароль и нет почты: `/admin/` → Пользователи → ученик → смена пароля. Указал почту и не подтвердил: в `/admin/` у пользователя включить «Активный». Новый аккаунт вместо старого не заводить: прогресс разделится |
| **«Потерялся прогресс»** | Чаще всего ученик вошёл под вторым аккаунтом: сверить логин в профиле и в `/teacher`. Если прогресс действительно пропал — это стоп-критерий: записать логин, шаг и время, приостановить занятие с кодом, сообщить разработчику. Ничего не исправлять в базе вручную |
| **Шаг не засчитывается при верном решении** | Записать шаг и код, сообщить разработчику. Стоп-критерий, если повторяется у нескольких |
| **Подозрение на утечку** (чужой вход, код преподавателя ушёл ученикам, данные без согласия в выгрузке) | 1) Сменить `TEACHER_INVITE_CODE` в Railway. 2) В `/admin/` сменить пароль суперпользователя и снять staff с лишних аккаунтов. 3) Если под угрозой ключи — сменить `DJANGO_SECRET_KEY` (всех разлогинит). **`ANALYTICS_EXPORT_SALT` не менять.** 4) Записать дату и что случилось; набор приостановить до разбора |
| **Сайт не открывается** | Vercel → Deployments: статус последней выкладки. Сервер: Railway → сервис → Deployments и Logs |

**Откат на прошлую версию:**

- Сайт: Vercel → **Deployments** → предыдущая строка со статусом Ready → **⋯** → **Instant Rollback** (или
  **Promote to Production**). Занимает меньше минуты.
- Сервер: Railway → сервис бэкенда → **Deployments** → предыдущая успешная → **⋯** → **Redeploy** (или
  **Rollback**). База при этом не откатывается; последние миграции только добавляли таблицы, старая версия с
  ними работает.
- После отката записать дату и время: эти часы, возможно, придётся исключить из анализа.

## 6. После пилота (после 28 декабря)

На своём компьютере, PowerShell, из папки проекта. Публичный адрес базы: Railway → Postgres → **Connect** →
**Public Network** → строка `DATABASE_URL`. Соль — та же, что на Railway.

```
$env:DATABASE_URL="<публичный адрес Postgres>"
$env:PILOT_STARTED_AT="2026-11-16T00:00:00+05:00"
$env:PILOT_ENDED_AT="2026-12-28T00:00:00+05:00"
$env:ANALYTICS_EXPORT_SALT="<та же соль, что на Railway>"
$env:DJANGO_SETTINGS_MODULE="core.settings.local"

cd backend
..\.venv\Scripts\python.exe manage.py pilot_report --contacts ..\contacts.csv --out ..\final_report.md
..\.venv\Scripts\python.exe manage.py pilot_report --json > ..\final_report.json
..\.venv\Scripts\python.exe manage.py export_learning_data --out ..\analytics_export
..\.venv\Scripts\python.exe manage.py export_risk_features --include-performance --out ..\risk_features.csv --performance-out ..\performance.csv

cd ..\ml
..\.venv\Scripts\python.exe -m pip install -r requirements.txt
..\.venv\Scripts\python.exe -m risk.train --features ..\risk_features.csv --performance ..\performance.csv --out ..\risk_model
```

Что получится:

- `final_report.md` и `final_report.json` — H1–H4 с интервалами;
- папка `analytics_export` — шесть таблиц CSV, только согласившиеся, псевдонимы вместо логинов;
- `risk_features.csv`, `performance.csv` — данные для модели;
- `risk_model\report.md` — сравнение модели с простыми планками.

Важно:

- `pilot_check` с этими локальными настройками всегда покажет FAIL — здесь его не запускают, он для сервера;
- если `risk.train` завершился сообщением о нехватке данных (в том числе английским «Found array with 0
  sample(s)») — это не поломка: ушедших учеников слишком мало, в диссертацию идёт описание метода;
- файлы выгрузки не класть в git и не пересылать в открытых чатах; хранить там, где решено в согласии;
- `RISK_MODEL_PATH` на сервере не задавать, пока нижняя граница интервала разницы ROC AUC с лучшей планкой не
  выше нуля (правило из `PILOT.md`);
- после выгрузки закрыть сессию PowerShell: в ней остался адрес боевой базы.
