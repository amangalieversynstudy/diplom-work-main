# Что сделать в Railway и Vercel

Коротко и по порядку, на 20–30 минут. Подробный вариант с пояснениями и действиями на случай сбоя лежит в
`LAUNCH_CHECKLIST.md`. Названия кнопок в панелях даны по их документации: если кнопка называется чуть иначе, ищите
по смыслу.

**Сначала подтвердите даты пилота.** Ниже стоят даты примера: пилот с 16 ноября по 28 декабря 2026 (6 недель).
`PILOT_STARTED_AT` должен быть **днём первого занятия**: кто зарегистрировался раньше, в исследование не попадёт.

## Шаг 1. Vercel: чтобы сайт обновился (5 минут)

1. vercel.com → ваш проект (`rpgacademy`, адрес `diplom-work-main-frontend.vercel.app`).
2. **Settings** → **Environments** → **Production** → **Branch Tracking** → выбрать `feature/final-polish` →
   **Save**. В старом интерфейсе: **Settings** → **Git** → **Production Branch**.
3. Вкладка **Deployments** → верхняя строка с веткой `feature/final-polish` → меню **⋯** → **Redeploy** (или
   **Promote to Production**). Подождать статус **Ready** (2–4 минуты).
4. Проверка: на сайте Ctrl+U, Ctrl+F, `buildId`: значение должно **отличаться** от `Fbi8zizqFtfvEyO5mQEXs`.

Если в логе сборки ошибка `Module not found`: этого быть уже не должно, исправление отправлено (`31f3f11`).
Тогда пришлите лог.

## Шаг 2. Railway: переменные сервера (5 минут)

Railway → проект → сервис **бэкенда** → вкладка **Variables** → **Raw Editor** → вставить, подставив свои значения:

```
PILOT_STARTED_AT=2026-11-16T00:00:00+05:00
PILOT_ENDED_AT=2026-12-28T00:00:00+05:00
HELP_OFFER_SHARE=50
SOCIAL_ENABLED=0
ANALYTICS_EXPORT_SALT=<случайная строка>
TEACHER_INVITE_CODE=<свой код для преподавателей>
FRONTEND_URL=https://diplom-work-main-frontend.vercel.app
```

- **Время обязательно с `+05:00`**, одна дата без времени не работает.
- **Случайную строку** получите в PowerShell в папке проекта:
  `.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"`. Для кода преподавателя
  выполните то же с числом `12` вместо `48`. Оба значения **сохраните у себя** (менеджер паролей): соль нужна при
  выгрузке данных и меняться не должна до конца пилота.
- **Должно быть удалено**, если есть: `ENABLE_STREAK_SCHEDULER`, `RISK_MODEL_PATH`,
  `RUNNER_ALLOW_UNSAFE_FALLBACK`, `ALLOW_DEMO_SEED`.
- После сохранения Railway сам перезапустит сервер (1–3 минуты). Во время занятия переменные не менять.

## Шаг 3. Railway: два задания по расписанию (10 минут)

Для каждого: **+ New** → **GitHub Repo** → тот же репозиторий, ветка `feature/final-polish`. В **Settings** нового
сервиса: **Dockerfile Path** = `Dockerfile.backend`; затем **Custom Start Command** и **Cron Schedule** из таблицы.

| Название | Custom Start Command | Cron Schedule | Зачем |
|---|---|---|---|
| snapshot | `python manage.py snapshot_early_warning` | `0 19 * * *` | каждую ночь записывает список «Срочно / Внимание» (нужен для гипотезы H3; пропущенный день не вернуть) |
| prune | `python manage.py prune_learning_data` | `0 3 * * *` | чистит журнал старше срока хранения |

Обоим сервисам нужны **те же переменные**, что у сервера: проще всего подключить **Shared Variables**. Минимум:
`DATABASE_URL`, `DJANGO_SECRET_KEY`, `ALLOWED_HOSTS`, `PILOT_STARTED_AT`, `PILOT_ENDED_AT`.
Проверка на следующий день: в **Logs** сервиса snapshot строка `snapshot <дата>: N learner(s)` или `nothing to do`.

## Шаг 4. Преподаватель пилота (5 минут)

1. Преподаватель регистрируется на сайте: «Я преподаватель», код из `TEACHER_INVITE_CODE`.
2. Вы открываете `https://diplom-work-main-production.up.railway.app/admin/`, входите суперпользователем →
   **Пользователи** → этот преподаватель → включить **Статус персонала**, **снять** флаг **преподаватель** →
   **Сохранить**. Без этого он не увидит учеников встроенных курсов.
3. Закрепить за ним встроенные курсы (команды на сервере, шаг 5):

```
python manage.py set_course_owner python-intro <логин_преподавателя>
python manage.py set_course_owner python-continued <логин_преподавателя>
python manage.py seed_demo_cohort --remove
```

## Шаг 5. Проверка сервера одной командой (5 минут)

Один раз установить Railway CLI (`npm i -g @railway/cli`), затем в PowerShell в папке проекта:

```
railway login
railway link
railway ssh
python manage.py pilot_check
```

`railway link` спросит проект и сервис: выберите бэкенд. Внутри `railway ssh` команды идут на самом сервере.
Результат: **ни одной строки `[FAIL]`**. Строки `[WARN]` про публичный Judge0, про почту и про Мудреца ожидаемы.
Выход: `exit`.

## Шаг 6. Остальное до старта

- Railway → **Postgres** → **Backups**: включить ежедневные копии и сделать одну вручную.
- Информационный лист для учеников (`PILOT.md`, раздел 3): контакт; код запускается на стороннем сервере Judge0;
  Зал славы открыт без входа; код последней попытки хранится. Согласовать с научным руководителем.
- Если на занятии будет 30 человек: ключ Judge0 на RapidAPI и переменные `RUNNER_JUDGE0_KEY`,
  `RUNNER_JUDGE0_CONCURRENCY=8`. Без них код проверяет бесплатный общий сервер: запуск может ждать 5–15 секунд.
- Почта (`RESEND_API_KEY`) на пилот лучше не включать, пока не проверена доставка: с включённой почтой ученик,
  указавший e-mail, не войдёт, пока не откроет письмо. Ученики регистрируются **без почты**.

## Если что-то сломалось

| Что | Что делать |
|---|---|
| Сайт на Vercel не обновился | проверить, что в Deployments у верхней строки метка Production и ветка `feature/final-polish`; сделать Redeploy |
| Сервер на Railway не стартует после смены переменных | вернуть прежнее значение последней изменённой переменной; **Deployments** → предыдущий деплой → **Redeploy** |
| `pilot_check` показывает `[FAIL]` | текст строки говорит, чего не хватает; чаще всего это дата без `+05:00` или нет преподавателя |
| Снимок за вчера не записан | проверить Logs сервиса snapshot и что у него те же переменные, что у сервера |
